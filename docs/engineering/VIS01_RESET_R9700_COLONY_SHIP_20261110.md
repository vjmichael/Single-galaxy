# VIS-01 — playable original-world reset, R9700 draw distance and retro-industrial colony/ship

## Why this task exists

The physical Radeon AI Pro R9700 operator demonstrated the earlier native pilot truly moves (0 and 250 mm/tick, multiple headings), but being lost in space is not a reasonable reason to delete all Godot AppData. A game must provide a human-initiated New Game option. The operator also requested a larger view range, genuine SGDX assistance and colony / ship presentation consistent with the earlier hard-SF / 1977 industrial design direction.

VIS-01 is **not** release authorization; it follows exact-head Group 2 / WO3–WO5 branch `73d9088bda4c590605c0f1456095d16ebde80ac4` (the two Windows/Linux workflows completed success) and does not merge, replace or bypass the upstream accepted native ownership and industry work.

## Player UX

**New Game button** is visible in the game, accessible while flying/lost, with **F6** shortcut. It opens a plain-language OS/game confirmation. Cancel keeps the active world. Confirm gracefully stops both SGDX native writer sessions, disables local input, waits for the guardian processes to exit and releases the SQLite lease. Only then does a durable journal record the archive request; recognized original world files (`single_galaxy_station_test.sqlite` and `single_galaxy_authoritative.sqlite`, WAL, SHM, journal and matching .diagnostics folders) are **moved—not erased** to `user://world-archives/world-<timestamp>`. A recoverable archive manifest is preserved and a native station host is started to create the fresh original world. No second writer or client-side fabricated station. Other Godot user data is untouched. The test-only fault injection checks rollback. A pending journal on restart blocks new-world creation until the archived original is fully restored. A failed process handoff or partial move blocks reset rather than trying a destructive workaround. The owner needs to verify this on installed Windows; the code and smoke are not equivalent to a physical pass.

**SGDX Diagnose** button or **F5** generates a human-readable local report of the current *verified* original SHIP tick, generation, dock state, station range, connected C++ writer roles, Godot FPS/frame p95, adapter name, draw clip, and up to five sanitized actual original supervisor custody receipts from `single_galaxy_station_test.sqlite.diagnostics`. A structured report is automatically added to the operator's local evidence folder (F11/F12 archive), if launched through the packaged build. It never reads minidump memory, changes the game, or sends the report online. This diagnostic view is meant to be useful to a normal pilot, not to require the user to parse raw logs or delete AppData.

**F4 visual quality** toggles Balanced and High. The Radeon AI Pro R9700 is identified by the Godot adapter name; High is the initial policy when the adapter contains `R9700` (identification alone is not GPU acceptance). Balanced clip 1.8 km / 310 efficient star instances; High clip 8.5 km / 1550 instances. Stars are a non-colliding inertial background, **not original asteroids or resource locations**. The original C++ same-tick station-relative NAV now places a visible station transponder out to the selected camera clip, with authentic distance and bearing always available on HUD. Distant geology beyond existing station walls is visual only; it is not a newly generated planet.

**Colony design:** pressed ceramic and rough textured weathered metal, repeated pressure-envelope ribs, stamped service doors, dark structural gantries, coolant trunks, roof radiators, mast and navigation cues. In-world signage has normal occlusion (previous forced no-depth signs overlapped all over the screen). The ship gets a triangulated tapered pressure hull and nose, armored swept wings, paired exposed engine pods, glowing exhaust, canopy, radiator slits, physical nav lamps and hazard striping. The station-display cladding and flight model are **one already existing ShipID**, not a new built ship. No new real settlement, construction, inventory, manufacturing equipment or colliders appear from these art changes.

## Honest constraints and next development

The older nearest-original-asteroid tactical contact sensor is still limited to **30 metres**; increasing a Godot camera clipping plane does **not** magically give the ship a longer original-world asteroid sensor. That requires a separate bounded, C++ verified long-range visual survey and streaming/LOD task—without replacing collision physics or fabricating resource targets. The prototype meshes and procedurally textured PBR materials improve silhouette and architectural language but are **not yet film-grade detailed models or photogrammetric surfaces**. A later specialist asset pass should add detailed glTF/USD meshes and proper LOD/material systems, not turn the native game into a second simulation.

**Still needed for release**: exact-head native Windows/Linux 19+33 suites, Godot parser/real scenes/new reset/DX/VIS smoke, Windows extracted bundled ZIP and non-headless frame/SQL restart, then operator test on physical R9700 (actual New Game archive/restart, no lost originals, improved colony visual/flight quality, p95/p99 and original station navigation). No final release/merge before all gates.
