# COLONY-EXIT-01D — Native Host Automatic Voluntary Migration Supervision

**November 4, 2026.** Branch `integration/colony-exit01d-host-auto-scheduler-v89-20261104`; stacked upon unmerged EXIT-01C personal history PR #29 and EXIT-01B genuine physical migration PR #28. No voting, petitions, fictitious personnel or compulsory leadership replacement.

## Host cadence and liveness

The actual `src/colony_live_host.cpp` desktop-host world loop calls `world.supervise_voluntary_migration()` after an authoritative world step at multiples of eight simulation ticks. The host rotates through at most four real colony ships per due cycle, and each colony examines up to eight named residents (API supports budgets 1..32). Eligible physical named residents are read in stable NPC-ID order; each scan rotates its starting point deterministically based on the tick. Unfounded colonies with no actual historical government are skipped; the host does **not** silently appoint a governor. No client data or player command can create an NPC appraisal by proximity alone.

`PersistentWorld::HostVoluntaryDepartureSchedule` also allows the trusted host to call the same coordinator with an approved receiving-owner route. The coordinator automatically allocates monotonic personal observation event IDs from the durable SQLite journal unless the host has reserved an explicit range; all duplicate observations at the same world generation are ignored, with the eight-simulated-tick spacing still enforced by EXIT-01C. Real world snapshots and previous-generation GRSM relationships remain the only inputs to discontent scoring.

## Decision and immigration progression

1. **Observe:** inspect a bounded rotating sample of real named colony residents. If eligible and due, publish an EXIT-01C personal appraisal. Distress is individual, evidence-based, time-spaced, and can recover after improved living conditions. No action occurs merely because an NPC is living under one shortage.
2. **Seek:** only a resident with a *previously committed* active personal intention and a still-active latest intention may progress. Among genuinely eligible residents in the current bounded sample, prefer higher discontent with a modest directional negative-leader-rapport tie-break. This is deterministic, not a vote or collective petition.
3. **No offer:** preserve the personal state; report `SeekingDestination`. No foreign colony or ferry is invented. The host UI can show migration interest for an existing named resident without implying the departure has happened.
4. **Trusted offer:** first-party host/permission broker must have authenticated the destination owner and supplied their exact approved destination, ferry, transport ID and durable admission/boarding identifiers. The coordinator checks real destination owner and life support, actual ferry ownership, same-system boarding location and range, no dependent-household risk, and existing real NPC identity. No arbitrary external client can bless another owner's colony by supplying a numeric owner ID.
5. **Immutable admission:** a genuine stored EXIT-01A physical shortage witness is reused or created (only if currently Critical/Emergency), and the native EXIT-01B `record_voluntary_immigration_admission()` binds a nonzero personal-decision event to a known receiving owner. Any outstanding unresolved admission for that resident is detected and cannot silently be replaced.
6. **Boarding queued:** `submit_voluntary_immigration_boarding()` sends the original authoritative HostEmbarkPassengers command. It is executed only on a subsequent canonical committed world tick. Crash or callback repetition cannot multiply the passenger or count a queued boarding as a completed migration.
7. **Arrival and settlement:** unchanged existing real gate travel, HostDisembarkPassengers, HostSettleMigrant and atomic ART02 family/ECON03 regional population transfer. The coordinator currently initiates arrangements and boarding, **not** automatic navigation, family closure, or final settlement. Those retain the original trusted native transportation/society gates.

## Durability and boundedness

Observation replay reads `sg_colony_npc_personal_outlook` and original world snapshots; auto-assigned IDs use committed maximum +1 with SQLite collision refusal. The same generation may be polled repeatedly with no second appraisal. Host rotation uses tick-derived stable indexes rather than ephemeral random cursor. Boarding uses pre-existing host command IDs and native writer permissions; an accepted but not yet boarded admission remains a durable pending record that can be retried with the exact same destination, ferry and manifest. A new route cannot overwrite it. Missing or unsafe destination is a non-destructive refusal.

Run only inside trusted host boundaries. The `HostVoluntaryImmigrationOffer` object is a **declaration by the authenticated host that approval was obtained**, not a signature verification or self-issued permission. Actual provider consent/policy APIs remain an integration task; direct user-facing access to this struct is forbidden.

## End-to-end native acceptance

`tests/COLONY_EXIT01D_HostMigrationSchedulerTests.cpp` constructs separate owner-7 origin and owner-10 receiving settlements, a real stocked ferry and stargate, physical scarcity, actual GRSM-directed contrasting NPC histories, and a real fixed-tick world. It proves wrong tick returns `NotDue`; the first cadence records five observations (not the leader), same-tick rerun produces none, next cadence leads to individual exit intention but not an immediate voyage, and the third due assessment prioritizes the personally aggrieved resident. No receiver offer means no person changes location. Spoofed receiving owner returns route blocked; a trusted valid offer automatically registers the real source witness, immutable admission and **queues** exact ferry boarding. It checks same-tick duplicate refusal, next-tick executed passenger movement, actual gate transit, real destination arrival, original atomic ART02/ECON03 settlement 6/6→5/7, crash rollback at settlement, restart, recovery, and forged admission/route refusal.

The CI workflow compiles `galaxy_colony_live_host` and runs earlier personal-history recovery, real EXIT-01B immigration, scarcity witness, GRSM directed social evidence and v59 adult+household migration tests. Report pass only after GitHub has run the exact executable revision.

## Deliberate limits

An approved receiving-owner offer is not made automatically from a discovered friendly colony: permission and immigration policies (Open/Closed, talent/age/permit filters) require an authenticated native policy interface. The first route only takes a single child-free adult. Guardian/family custody must never be bypassed. Autonomous route-finding, ferries re-routing, mid-flight incident response, cross-owner acceptance protocol, complete arrival/settlement supervisor, explicit separate `HostVoluntaryMigrationOffer` durability/signature and Windows hardware acceptance are separate gates. The host records interest even when no route is available; a resident cannot disappear without real transportation.
