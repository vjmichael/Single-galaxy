# WO5 — Physical transport, logistics, and resource-demand integration
**Opened 2026-11-07**, owner-directed Stage 5. Branch `industry/wo5-physical-logistics-20261107` stacks on WO4 draft PR #91; WO4 stacks on WO3 #89.

## Binding architecture and scope
- The game begins with finite physically constructed ships, planetary shuttles, storage, fuel and original NPC pilots. No free carrier, automatically completed shipment, arbitrary planetary goods, transport speed, trade credit, wage or material creation.
- `Simulation` and `PersistentWorld` remain the only stock, NPC and ship authority. Original `UniversalTransport`, `IntercolonyFreightLeg`, `LocalDeliveryOrder`, `ThirdPartyRegistry` and `RegionalHostCommands` already exist; WO5 must extend/compose rather than replace them.
- WO4 `CarrierRequest` and `ProposedMaterialFreight` are **read-only unbooked suggestions**, never arrival receipts or owner approvals. Every operation must be owner-authenticated by the trusted host and recheck the current original world, not a copied demand snapshot.
- The actual original local pickup supports **Water, Food, Nutrients**. The original two-leg sealed intercolony freight supports these same three, NOT oxygen or arbitrary manufactured objects. The separate original planetary shuttle supports Water, Food, Nutrients, Oxygen for one local trip. Finished panel/frame cargo has its own original `ThirdPartyRegistry` path and requires real constructed workshops, distinct owner approvals and warehouse custody.
- WO3-F remains open due pre-runner CI infrastructure; WO4-F remains open until genuine native test logs. Neither blocks Stage 5 development. Native Windows 3D installed-game acceptance stays deferred until genuine 3D assets.

## WO5-C — Manufactured finished-goods logistics (2026-11-07)

**Status: source integration implemented on [draft PR #92](https://github.com/vjmichael/Single-galaxy/pull/92); native acceptance remains OPEN.** This task is limited to the **two actual native v53-produced factory-return classes**, `good/aluminum_panels` (native ThirdParty index 1, network `plates`) and `good/aluminum_frames` (native index 2, network `frames`). Raw aluminum, scrap, food, generic catalogue assets and unreleased recipes are **not** eligible for the original three-owner finished-goods shipping route.

### Real original-world interfaces
- New `include/galaxy/WO5ManufacturedFreight.hpp` converts a **recipient-declared `economy04::MaterialNeed`** (real physically constructed receiving warehouse, priority and required quantity) into an ephemeral offer for a **specific original factory-returned physical lot** in an existing source warehouse.
- The older `economy04::ProposedMaterialFreight` remains **one-owner and unbooked**. This three-owner shipping path must never reinterpret it as consent by an independently owned receiving colony. Instead the trusted host authenticates the recipient's declaration, and source owner later makes a separate authenticated booking request. Both are merely admission claims until the existing SQLite shipping host records original consignment evidence.
- Preflight requires THREE distinct real owner IDs and original physical ships; real built source and receiver warehouse custody; origin-site/carrier in the correct original system; distinct physical destination system; actual original `goods_kg` panels/frames at the source; zero same-material carrier cargo; volume available in the actual carrier and receiving 4m³ storage; 1–1000 kg per original native consignment; bounded recipient-declared quantity; canonical shipping/receipt IDs. Proposal is **read-only** and stores no material or reservation. This proposal **does not certify factory manufacturing**.
- `book_manufactured_consignment` refreshes the original world hash, tick, original owners, inventory and receiver capacity, then calls **`CanonicalShippingHost::book`** with the authenticated source principal and required canonical v57 dispatch policy. The existing `ProductionShippingHost::book_factory_goods` checks the **original v53 `sg_v53_world_return` SQLite factory proof** for the exact `plates`/`frames` item, source site, source ship and amount, then the existing `ThirdPartyRegistry` commits the unique v56/v57 booking and prevents colliding cargo reservations. An offer with an unverified or mismatched factory-return command cannot pass that host.
- Original separate immutable source-owner (role 1), carrier-owner (role 2) and receiving-owner (role 3) approvals are **not** auto-created by WO5-C. The original `CanonicalShippingHost::approve_booking`, carrier-only dispatch/load, native exact movement receipts, real `Action::RequestJump`/proximity to the independently built destination warehouse, carrier-only unload and carrier+receiver `acknowledge_delivery` still operate without new inventory or shortcuts. Host-only consignment commands never become client commands.
- `include/galaxy/WO5ManufacturedEvidence.hpp` is a read-only reconciliation of `ShipmentStatusView` (SQLite original custody receipts) against actual original physical warehouse and carrier stock. It distinguishes unsigned booking, dispatched but unloaded, physically loaded/in transit, genuinely received, and two-owner settled; returned or redirected consignments are **not** misreported as direct fulfillment, and an unrelated caller receives no shipment record. The existing v57/v58 return/redirect interfaces still own those outcomes, not a duplicated WO5 control plane.
