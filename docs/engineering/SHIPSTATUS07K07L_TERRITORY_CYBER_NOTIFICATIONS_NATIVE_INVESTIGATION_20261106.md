## 07K — same-transaction, owner-bound territorial and cyber notification sources

The previously implemented `ShipNotificationOutbox.hpp` was a complete **at-least-once consumer/ACK** for original ship-to-ship communication and 07J referrals, but it did not automatically cover the original territorial and cyber journals. 07K now makes **those journals the actual producers**:

- `TerritoryJournal::append` atomically inserts the already validated original immutable territorial event and the independently addressed notifications in the SAME original SQLite transaction. Notifications cover claimed jurisdiction and invitation/revocation decisions (kind 8), witnessed warning (9), original notice ACK/refusal (10), witnessed trespass (11), expulsion (12) and voluntary authenticated hail (13).
- `CyberIncidentJournal::intake` atomically inserts the same-tick independently witnessed cyber case and private original colony-owner/victim-owner notifications (kind 14). The actual attacker remains **unidentified**; no sensor silhouette or guessed account ID is emitted. If the victim owner differs from the observing colony owner, the victim receives only its own damaged/targeted ship identifier, not a foreign watcher's hidden attacker track.
- `CyberIncidentJournal::link_authenticated_hail` atomically links every qualifying older case in the canonical casebook and emits ONE owner-specific follow-up notice for the current, later verified controller (kind 15). The notice is one **later identity update**, not a retroactive crime attribution or identification of the earlier pilot. A single hail may link several older cases, all of which stay independently queryable in the source journal. A repeated link pass for the same genuine hail is idempotent for notification routing when its original hull/controller match, rather than rolling back newly discovered case links.
- Private routing is to the **committed native account identities** at the time of the event. Normal unaccepted/silent warnings do not silently reveal the visitor account; a deliberately voluntary identifying hail may expose that owner only to the original receiving jurisdiction. Every notification has the original event reference, a real relevant physical hull, and optional related original receipt, never a guessed contact.
- **Legacy migration:** old `sg_ship_notifications07i` saves have `CHECK(kind BETWEEN 1 AND 7)`, which SQLite cannot ALTER directly. `Outbox::ensure_schema` detects exactly that legacy constraint and uses one rollback-safe `BEGIN IMMEDIATE` rebuild to preserve old `seq`, `acked`, original account routing, peer/source/related fields and current autoincrement while extending allowed kinds to 15. This is a **schema migration only**, not unverified historic recipient backfill.

The authenticated `SECURITY_REFRESH` path already returns a page of unacknowledged originals, and `SECURITY_NOTIFICATION_ACK` is validated by the original native owner. Original `SECURITY_...` browser parsing renders kinds 8–15 with explicit non-attribution language, submitting exact owner-scoped ACKs only after rendering. SSE overflow and host crash cannot erase unacknowledged records. It is **at least once** until native ACK, not lossless historical streaming of unrelated telemetry.

**Regression source:** `tests/SHIPSTATUS07D_SecurityDeskTests.cpp` now injects a SQLite failure on cyber owner-notification insertion and proves the original incident also rolls back, then admits a legitimate retry. It proves private claim, unknown-offender cyber, voluntary identity, original warning, native notice decision, later link, wrong-owner ACK and canonical copy/restart. `tests/SHIPSTATUS07I_DurableOutboxTests.cpp` includes a deliberately constructed exact old-schema fixture preserving both ACK states and original sequence IDs through the 7→15 migration, then commits a new kind-8 territorial notice. `tests/SHIPSTATUS07I07J_SecurityDeskTests.js` covers parser schema/non-disclosure and rejection of forged kind-14/15 identity claims.

## 07L — authorized, supervised NPC investigation using EXISTING flight/work systems

The existing `ColonyLawAgency.hpp` already validates an **original signed nuisance referral**, territorial claim, living appointed government, distinct physically present on-duty agency officer and independent third-NPC reviewer. 07L adds an investigation **work adapter**; no alternative NPC AI, workforce engine, navigation, combat or security authority was built.

Admission requires all of the following, at native command time:

1. An authenticated primary account owns the same actual existing colony and its original territorial claim is still valid. Secondary security-only players cannot order or manipulate patrols.
2. The agency appointment still matches the genuine current `GovernanceEpoch` and a finite named on-duty officer. The immutable referral belongs to that owner/colony/government/officer, has a credible previously reviewed complaint, and supplies the authenticated caller account.
3. The proposed target is a **currently existing, physically local foreign hull** whose current native owner matches the reported caller account. This is a lead to a current account-operated hull, **not proof it performed an earlier offense**.
4. A separate named, duty-eligible NPC on the original responding colony ship independently witnesses the exact currently observed contact from `local_colony_watch_contacts`. The hostile client cannot supply the watcher, actor identity, sensor result, ship position, warrant, pilot or law policy.
5. The nominated officer and witness pass existing `npc_available_for_duty` and the canonical `WORK-01B.2` `work::index_native_capacity` busy-build reservation check. Existing active NPC flight pilot assignments are also honored. No one is cloned, paid, teleported or assigned over an active native job.
6. The original owner-native `npc_response::dispatch_observed_patrol` does **all** physical re-observation and `PersistentWorld::queue_npc_ship_rendezvous` admission. This reuses `NpcFlightPurpose::Patrol`, its real `NpcFlightOrder`, normal physical move/velocity rules, finite crew and source-world SQLite persistence. It performs **approach/rendezvous only**. No police craft is summoned.

### Crash-safe two-ledger protocol

The nonviolent intent is recorded once, immutably, in `sg_law_investigations07l` with original referral/owner/government/officer/witness/target and an original native flight order ID. The source may crash after intent COMMIT but before the original world can accept its physical NPC flight. The UI **never** equates that intent to flight admission: `Agency::investigations` reconciles every read against the original native `npc_flight_orders()` and checks owner, physical ship, same officer, target, mode `LocalRendezvous` and purpose `Patrol`. Without that authoritative order the read model explicitly says **"native flight NOT admitted"**. A retry revalidates current owner, governance, territory, staff and exact live witness, then uses the SAME reserved original flight ID; it never fires a duplicate native mission or silently upgrades unsupported permissions.

Once admitted, only the ORIGINAL `NpcFlightPhase` drives planned/in-transit/arrived/cancelled status. An arrival alone grants no docking, search, forced hailing, boarding, custody, arrest, seizure, or weapon authorization. Subsequent case review, follow-up, physical evidence collection, procedural justice, disposition and any lawful coercive authority require distinct future gates. This initial investigation intentionally approaches with an **existing actual colony ship**, not a fabricated separate patrol fleet, and may be refused by normal native navigation if that vessel is busy or unsafe.
