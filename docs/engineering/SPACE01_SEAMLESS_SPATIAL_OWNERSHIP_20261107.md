# SPACE-01–03 — Seamless 3D spatial cells and native computational custody

**Opened 2026-11-07 — architectural prerequisite requested before returning to WO5-E/F.** Branch `space/seamless-spatial-ownership-20261107` stacks on [WO5-A–E draft PR #92](https://github.com/vjmichael/Single-galaxy/pull/92), which in turn stacks on WO4 #91/WO3 #89. This is a **spatial-ownership foundation**, not a claim that the legacy movement engine has already become full six-degree-of-freedom galaxy flight.

## Non-negotiable player/world invariants

- **One original continuous galaxy, not EVE-style physically bounded grids.** A computational cell has **no collision, ownership, obstruction, teleporter, access gate, or economic permission**. Ships may cross its mathematically invisible edges without touching gameplay resources.
- **One original `Simulation` / `PersistentWorld`** owns each ship ID, finite NPC roster, actual cargo, physics/jump receipts, colony inventories and gameplay commands. Workers and spatial indexing cannot create, clone, debit or credit people or cargo.
- **3D cosmic identity is original physical data**: `CosmicPosition{x_mm,y_mm,z_mm}` and the saved `ShipFrameCustody` anchor and origin; `Entity.position/velocity` are the current **bounded legacy 2D local projection**. Spaces are differentiated by their real original system IDs; no single shared local coordinate is silently treated as cosmic.
- **Native compute responsibility is not player ownership or region sovereignty.** It is a host-authorized, epoch-fenced worker lease for a **cell ID**, independent of the original ship owner. Regional `Cold/Detailed` ownership remains `RegionalModeAuthority` and original checkpoint/receipt writer; the worker lease is not a second canonical simulation.
- **No galaxy-wide freight stop for an unrelated, verified spatial cell.** The native physical fret safety fence checks original source/carrier/destination ship cells. **Legacy arbitrary named region scopes** without a trusted physical cell binding retain their prior global conservative freeze. No fabricated native ship→region identity mappings or missing-receipt optimism.

One index row per original physical `EntityType::Ship`; a change in cell writes one immutable `sg_spatial_native_transfer` receipt with original ship ID, player owner, previous and new cell, original world generation and hash. Unmoved ships simply update their derived observation epoch; retired ships disappear from the **index**, never from original wreck/cargo data. `sg_spatial_native_meta` anchors world generation/hash/count; `verify_native_index` checks original live ship IDs, physical cosmic position, owner, current cell, immutable latest migration receipt and absence of forged extra rows. No serialized parallel gameplay entity state.
- `src/Persistence.cpp`: `spatial::record_native_world_commit(db_,state,expected_generation,next)` executes after writing the canonical native `snapshots` + `operation_log`, but before the one original SQLite transaction commits. Injections like `FailPoint::AfterSnapshotWrite` roll back cargo, ship motion, spatial index and movement receipts together.
- `include/galaxy/SeamlessCellWorker.hpp`: `transfer_cell_worker` is a trusted-host invocation. It takes the canonical native physical DB, exact cell, authenticated host approval, worker identity, region epoch/revision, prior worker epoch and unique durable transfer ID. It uses **one `BEGIN IMMEDIATE` on the same DB**, verifies current original physical snapshot/index and stable `RegionalModeAuthority` epoch, then applies monotone CAS and appends an immutable worker handoff. - `include/galaxy/WO5RegionalFreightFence.hpp` and `src/RegionalModeAuthority.cpp`: prepare and commit both receive the actual requested regional scope, read original canonical world under their transactional authority, require original arrival for completed freight, and protect **only spatial regions actually containing involved ships**, provided a full current binding index is verified. - `include/galaxy/WO5RegionalRecovery.hpp`: read-only audit checks exact original world+region SQLite filename, world generation/hash, regional epoch/revision and v59 manufactured custody witnesses. ## Native SPACE-04A geometry foundation — exact galaxy-scale millimeters

The previous `CosmicPosition` type uses signed 64-bit **millimeters**, whose absolute range is less than one light year: it is appropriate for an astronomical local frame, **not** for galaxies spanning many thousands of light years. New `include/galaxy/GalacticCoordinates.hpp` introduces `galactic::Point` with a signed high-order *1e15 mm sector* per x/y/z axis and an exact normalized offset `0..1e15-1 mm` per axis. This covers actual galactic-scale distances with ample headroom, without using floats to accumulate movement, forming a physical wall at a sector edge, or requiring `__int128` unavailable on standard Windows MSVC. `advance(Point,Velocity)` carries exact 3D signed millimeters across sector boundaries with signed overflow checks, `at_system_origin(Point,CosmicPosition)` supports a future **explicitly registered and persistent** star-system placement, and `nearby_displacement` calculates local cross-sector 3D relative vectors only when representable, without subtracting gigantic distant coordinates. `galactic::Cell` uses sector+within-sector cell indexes, not a single overflowing flat integer.

`tests/SeamlessSpatialOwnershipTests.cpp` adds pure geometry assertions for a far-away position spanning 946,073,000 sectors in each direction, simultaneous three-axis crossings (including negative and vertical motion), exact cross-sector displacement, `INT64_MIN` normalization, `INT64_MAX` outward overflow refusal and future system origin relative offset. This is **reusable geometry only**: a new host-controlled native star-origin registry now permits explicit real galaxy placements, but `Simulation::step` is **still bounded 2D**, and the game cannot yet fly through these huge distances. SPACE-04B explicitly requires native source-of-truth migration rather than a parallel movement database.


### SPACE-04A.2 — Host-registered real star-system galactic positions

New `include/galaxy/GalacticSystemRegistry.hpp` provides **immutable `sg_galaxy_system_origin` mappings** of actual original `Simulation::systems()` IDs to exact normalized `galactic::Point`s, as permanent galaxy geography rather than a second ship/cargo/inventory record. Registration is trusted-host-only, requires a real registered native system ID, exact current original SQLite `snapshots` generation and world-state hash, bounded nonempty galaxy-generation manifest ID, and refuses changed coordinates or conflicting duplicate manifests after first commit. An exact repeated registration is idempotent. SQLite triggers prevent ordinary later update/deletion. `original_ship_galactic_position` then reads one system origin and projects the **existing original ship ID/frame/local position** into a precise galaxy-wide 3D point. No ship is moved, and unregistered stars return **no** invented position.

The native source test now creates **two actual star-system IDs in one original `Simulation`**, registers them to distant galaxy-sector positions, refuses unknown system 999, forged/unauthorized manifest and changed original star origin, confirms exact original ship position before/after real native `Action::Thrust`, and verifies origin geometry survives independent SQLite `recover_copy` unchanged. These original galaxy placements are host data, not player-mutable local walls. The full source-of-truth ship physics remains legacy 2D until SPACE-04B, but its future galaxy-scale coordinate basis is now durable.
