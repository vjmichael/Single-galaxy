## Source implemented

1. **Original-world shuttle transfer process:** `src/desktop_planet_transfer.cpp` is compiled as a second mode (`--planet-transfer`) of the EXISTING `galaxy_desktop_player_host` binary. It acquires the same `NativeWriterLease` and opens an existing `PersistentWorld`; it never constructs an alternative player, site, shuttle, ledger, physics loop or invented stock. It enumerates at most 16 genuine owned, crewed, operational original shuttle sites tied to the original PlayerPerson home ship. Any multiple-site choice is a bounded proposal; the C++ owner, exact key, source ship, real shuttle and physical body remain authoritative.
2. **One-human-action protocol:** typed `TSITE` and continuously journal-backed `TFRAME`, human `TSELECT` and `TDO` (BOARD, DESCEND, DISEMBARK, ASCEND, EXIT), strict per-process epoch / monotonically increasing request IDs and independently committed original SQLite receipts. Native `world.step()` continues every 100ms even with no Godot input; the preexisting original shuttle flight worker reaches actual landing/ascent in its original finite flight ticks. A false or unsafe action is denied by the original `PersistentWorld::planetary_player_shuttle_action` or `launch_planetary_shuttle`, never simulated in Godot.
3. **Installed handoff:** `desktop_godot/world/native_planet_transfer_session.gd` validates per-site identity and source/journal monotonicity, native `TLAND` and `TRETURN` receipts, and a 3-second no-frame/no-ACK watchdog. `planet_transfer_panel.gd` exposes explicit site selection and human actions. Main Godot F9 on an already-connected original cockpit uses its *actual SQLite pathname* and waits for guardian PID death before admitting the transfer writer. `DISEMBARK` transitions to the existing original surface host; `EXIT` returns to the original cockpit. No Godot camera/visual grants authority.
4. **Original hatch reboarding:** an E action while genuinely ashore issues `PREBOARD|SESSION|REQUEST|REBOARD` to the existing source-owned `--planet` host. The C++ host requires an original player within 2m of the actual local hatch, grounded, stationary vertically, with previously allocated O2 and exhaled CO2 returned to the same site. It commits the real `PlanetaryPlayerAction::Reboard` and sends a one-use `PLEAVE` after the original SQLite commit. Godot only then releases the surface writer and resumes `--planet-transfer`; `ASCEND` and `EXIT` remain separate explicit human actions.
5. **Recovery:** transport state is never persisted in a UI variable. A new `--planet-transfer` child reopens the original SQLite owner after native death, issues a new epoch, reconstructs already-boarded / in-flight / landed / returned PlayerPerson source custody and resumes native clock ticks without retroactive offline steps. The GUI supports **Shift+F9** explicit recovery of a saved in-shuttle voyage. Stale process IDs and stale shuttle epochs are denied; role handoffs require actual OS PID termination. New Game is blocked while either live planetary writer or a role handoff is active.
