# Dock District, Colony Inventory, Population LOD and On-Foot Movement

Engineering design and implementation register — 2026-11-11. **Development branch, not a verified release**. No routine CI, draft PR, native acceptance or packaging submissions are authorized during this building phase.

## Player-approved governing design

The dock is the interface between a physically situated colony and space. It is a **separate transport/logistics district** with a protected public boarding path, freight staging, and a named-worker dispatch area. The colony can have a population in the millions, but rendering and pathfinding every resident is forbidden. Its original simulation may aggregate people; only a bounded small fraction appears in Godot, and that display must never invent inventory, job outcomes or actual NPC identity.

Inventory has **EVE-like location custody**: one logical, private inventory for each owner at each colony/station (the native `(station EntityId, PlayerId)` hangar plus native owned station facilities). An item left at Colony A cannot be accessed at Colony B; it must be loaded into a physical ship and transported. Do not create an account-global stash or copy inventory into UI memory as a second authority.

The player's docked-ship ore is transferred by native `UnloadOre` to the exact owner's **colony station hangar**, not the avatar's pocket. Refining at Colony A works from the same colony interface and requires an actual original-world constructed, crewed, powered facility, with source lot, finite inputs and original SQLite commit receipt. The interface is permitted anywhere **inside that original colony**, so players do not have to walk to the actual refinery or factory for control. Physical construction, material transfer, equipment, NPC assignments and logistics remain real; only the operator's local console access is virtual.

Manufacturing/ship-module design is **deferred**; no artificial recipe or module provisioning may be used to fill the gap. The eventual manufacturing panel must issue original approved industry/workshop commands and deposit legitimate output at the **same colony**, not at a remote station or on the person.

On foot, pressing **Shift** toggles running ON/OFF; holding Shift is not required. Flight remains the original supervised third-person cockpit with separate inputs.

## DOCK-02 implementation — added in this task group (source only)

- `include/galaxy/DockLogistics.hpp` persists authorized dock-shift appointments and bounded service jobs in `dock_staff_v1` and `dock_jobs_v1` **inside the original saved-world SQLite file**. These tables reference existing named `NpcRecord` identities and original ship IDs; they contain **no ore, people, manufactured stock or second hangar**. One worker can hold at most one dock shift at a time in this table; shifts expire after 256 original-world ticks, and only a physically present same-owner named ship-role NPC free of known native workshop/medical/yard work may be assigned. Existing external workforce schedulers do not yet honor the dock reservation; this remains a cross-system integration gap.
- One station/owner can have up to **16 valid on-shift dock workers**, **128 outstanding jobs total** (including held jobs), and up to **64 tonnes in one finite, ship-backed freight booking**. Both booking and execution revalidate native original-world custody; a queue request does not claim that inventory moved. Passenger bookings require a real, physically present, same-owner named NPC and are **check-in only**, with no fictitious voyage or transport ID.
- `src/desktop_station_host.cpp` implements `DOCKVIEW`, `DOCKASSIGN`, `DOCKRELEASE`, `DOCKPASS`, `DOCKFREIGHT` and `DOCKWORK`, with original PERSON/session/generation/replay/45ms/colony locality checks. Worker auto-selection examines **at most 4096** original named NPCs (a truncated search may refuse without inventing staff). No extra writer process or account-wide supply is created.
- Work dispatch is bounded by the number of real available assigned workers: at most **min(active dock staff, 4)** original appointments per explicit dispatch. Cargo service uses the existing authoritative `Action::UnloadOre`, one real tonne per original `PersistentWorld::step()`. Stable command IDs are reserved *before* dispatch, so an interrupted post-commit acknowledgement can reconcile an original `Event`; missing/ambiguous evidence marks a job **held**, never automatically repeats ore transfer. A passenger check-in simply commits its appointment in SQLite; it does not alter physical passenger custody.
- `desktop_godot/world/native_station_session.gd`, `refinery_terminal_ui.gd` and `main.gd` expose worker assignment/release, status refresh, bounded passenger check-in, one-tonne physical freight booking and explicitly requested worker dispatch in the ordinary **I** colony panel. No raw IDs are required. Native `DOCK` receipts bind identity, station, queue bounds, generation and the outstanding request. `POPVIEW` now reports **valid assigned dock shifts** instead of mistaking a generic ship-role NPC for an employed dock worker.
- `tests/DockLogisticsTests.cpp` and CMake registration stage the first conservative false-worker/false-passenger/undocked-freight/restart checks. **They have not been executed. No native build, installed gameplay matrix, CI submission, PR verification or release acceptance is claimed.**

## DOCK-02 limits that still need implementation

1. **Original-world station staffing availability:** fresh-world starter ship crew generally remain aboard their own real ship. A genuine named-NPC disembark, local recruitment, shift-training and station custody path is still required for the first usable station shift. Never count crew merely because a ship is docked.
2. **Global workforce reservation:** existing workshop/yard/medical schedulers must reject a worker already appointed to a dock shift; the dock currently checks their duties on both assignment and actual execution but cannot prevent them being assigned a different job later.
3. **Continuous service:** the current native host advances queues only on an explicit creator dispatch; independent scheduled background work, shift handoffs, priority/fairness, passenger manifests and physical boarding/voyage admission are separate implementation work. A passenger check-in is **not** a completed travel.
4. **Recovery and lifecycle:** held jobs conservatively block reuse, but an owner-reviewed cancellation/reconciliation interface and a bounded archival/aggregate counter for lifetime queue history are not built yet. Existing direct manual one-tonne `COLUNLOAD` remains available outside this staff-scaled service queue.
5. **Scale:** the LOD caps are constant (24 civilian + 8 staff graphics), but colony-wide millions-scale cohort population statistics, aggregate traffic demand generation and owner-approved transport admission are not yet connected to the visible native named-NPC sample.

## DOCK-03 — Physical workforce integration (new source implementation)

**Development branch only; staged tests have not been executed.** No Windows/Linux native CI, PR verification, Godot installed acceptance or change to `main` was requested or performed.

### Original-world NPC movement and durable custody

- `src/DockWorkforce.cpp` adds trusted `Simulation::station_dock_worker_transfer`: a **specific original named crew member** may temporarily move from a physically docked, owner-matched original ship to its exact original station. Station ownership, physical berth, current NPC role/location, duty/transport/mentorship, active flight, scheduled undock and a minimum physical crew remaining aboard are checked. The same NPC can return to the same docked hull; no new NPC, fictional journey, account-global worksite or invented inventory appears.
- `PersistentWorld::station_dock_worker_transfer` commits the changed **canonical NPC physical location** with one original world STEP and an immutable `sg_dock_worker_moves` record **in the same SQLite transaction**. Fault injection must roll back both. Legal residence, original home ship and finite crew contract remain unchanged; a shore assignment is not permanent immigration or a second workforce roster.
- Owner-requested `DOCKASSIGN` now selects an eligible **named ship NPC**, physically moves them ashore first and only then opens their durable dock shift. `DOCKRELEASE` returns that person to their actual docked ship before deleting the appointment. Both are guarded against detached saves and cross-owner selectors. No general NPC is counted merely because it appears in a ship manifest.
- The original `PersistentWorld` player, supervised-cockpit, and trusted NPC-host flight submission paths deny departure while any named original crew member from that vessel is stationed ashore. The original ship-boarding/walking controls remain separate; a player must bring staff back before leaving.
- This is an **atomic berth-level shore-duty transition**, not yet independent NPC corridor walking/path animations, fully autonomous crew reassignment, or station life-support migration. Internal simulation-created NPC flights outside the guarded host-submission paths still require an explicit integration fence in a later group.

### Qualifications, shortage backpressure and automatic services

- `DockLogistics.hpp` resolves current assignments against **original station physical custody, docked home-ship ownership, active native workshop/yard/medical work and NPC duty availability**. An expired shift does not count as productive labor. The global world's original role, medical and industry records remain the source of NPC identity; the dock ledger only records temporary appointments and receipts.
- `dock_pending_worker_v1` preserves each original one-tonne unload's intended worker *before* execution. On an independently APPLIED original `Action::UnloadOre`, `dock_serviced_units_v1` records exactly one real worker credit, and queue progress/credit commit together. Restart reconciliation never mints a second credit from the same command.
- Basic station labor is limited to physically present, original ship-role crew (no fake trained strangers). After **three successfully applied tonnes**, the specific worker earns an *experienced cargo handler* status, based only on immutable actual work receipts. Each basic worker contributes at most one tonne per service cycle; an experienced worker may contribute two, and all throughput is capped at **four original-world operations per cycle**. Physical cargo, original inventory and journal still determine actual success.
- `native_station_session.gd` runs a **foreground automatic** dock-service dispatcher about once per 900ms **while the original station role is active**, idle and physically in the same colony. It checks native queue/staff status, then requests bounded `DOCKWORK` through the **same native writer and source receipts**; staff shortages, empty queues, boarding and disconnection stop it. There is no detached Godot SQLite writer or offline catch-up while the application is closed.
- The **I** colony panel now shows true available staff, source-backed experienced handlers, up-to-four-service capacity, queue sizes and physically unloaded tonnage. The original capped `24 + 8` presentation meshes are unchanged, and cannot invent jobs or physical populations.

## DOCK-04 — Real passenger and freight operations (implementation source)

**Development branch only, 2026-11-11; source committed, consolidated native and installed acceptance deliberately deferred.** DOCK-04 reuses the *original* finite `NpcRecord`, `ColonyShip`, life-support, `PersistentWorld`, SQLite and `HostEmbarkPassengers` voyage command. Its service queue is **not** an independent population, cargo or transportation authority.

### Original passenger boarding and berth capacity

- `include/galaxy/Dock04Traffic.hpp` introduces a bounded same-file SQLite station-traffic ledger: `dock04_boarding_v1` (one original named applicant / exact original home ship / specific distinct real ferry), `dock04_flow_v1` (fairness streak), and `dock04_embark_evidence_v1` (individually attributed source-verified voyage receipts). The ledger never inserts new original NPCs, ore, or ships. Only one active queue record per named person is permitted.
- Boarding requires an original owned home ship **and a different, original owned ferry**, both physically docked at the **same** original station and with original galaxy/system custody. The dock has at most **two available gangways**; original `Simulation::HostEmbarkPassengers` and its own **16 true ferry passenger berths** remain the final authority. Booking rechecks source crew headcount, all prior active reservations from the same ship, original physical ferry seats, existing passengers and finite two-cycle food/water/oxygen.
- One assigned real dock worker accompanies each boarding as a source-verified service credit. A boarding job runs original `home ship → station check-in → home hatch → ferry` where needed; both temporary berth transfers are journaled as original `sg_dock_worker_moves` physical-custody steps. The final step uses the native `Action::HostEmbarkPassengers` command through `PersistentWorld::submit_host_passenger_action` plus `step()`. A passenger is displayed as actually boarded **only after** the original APPLIED event, original voyage status and exact `npc.location=ferry,` `npc.transport_id=voyage` all match.
- Original NPC ship affiliation, permanent crew contract, same-owner custody, distinct ferry identity and population totals remain unchanged; the ferry's 16 real passenger berths, source crew and original life-support inventory constrain boarding. A passenger queue request never creates a voyage or teleports a resident.
- In-progress queue phases and immutable movement/boarding identities survive restart. Original-world uncertain outcomes become **held**, not automatically replayed. If an original queued voyage subsequently commits after a hold, a later read can reconcile that exact applied evidence without creating a second passenger.
- Genuine station staff conflicts were repaired at source: `Simulation::npc_available_for_shore_duty` validates the same original health, transport and flight rules for correctly stationed named crew. `Simulation::from_snapshot` now admits only original ship-role staff genuinely at their home ship's **docked station**, not an arbitrary other location. `PersistentWorld::Store::restore` separately requires the latest immutable `sg_dock_worker_moves` receipt to explain a living stationed original crew member.

### Shared passenger/freight capacity and priority

- `src/desktop_station_host.cpp` now admits `DOCKPASS` only for a real eligible named passenger and an original physically docked ferry. A `DOCKWORK` cycle uses the **same** actual named dock-worker roster for passenger and freight handling, dispatching up to **two real boardings** and **four total original work operations** in one bounded cycle. Freight still calls the original one-tonne `Action::UnloadOre`, with original asteroid lot, station hangar, and source worker experience; no second inventory.
- Boarding jobs are ordered by **native emergency source-colony safety** before stable queue ID. A persisted **two-passenger streak cap** directs the next available shared worker turn to freight if freight is outstanding, preventing permanent cargo starvation; successful original freight resets that streak. A queue/job cannot claim priority by an arbitrary client-supplied number. Congestion is calculated from real pending jobs and available physical gangways, never generated decorative people.
- The standard colony **I** panel and source-bound `DOCK` protocol display active workers, experienced handlers, validated local ferry gangways, waiting/urgent/held/actually boarded named passengers, real station freight tonnes, actual unloaded tonnes and congestion. The same original station authorization, generation/replay and one-use request checks still apply. Foreground automatic station-session scheduling remains bounded; there is no detached UI world writer.

### Large-population pressure without mass NPC materialization

- `PopulationCohorts::population_at(settlement)` sums true aggregate strata by **exact original settlement ID**, in time proportional to existing *cohort strata*, **not residents**. `dock04::projected_demand` performs fixed-point count mathematics (0–1,000,000 candidate requests per million), clamped to actual physical berth capacity; `Traffic::project_cohort_pressure` binds that count to an actual original station and caps displayed demand at `real gangways × 16`. A million/billion residents remains a bounded numeric projection.
- **No numeric cohort pressure ever creates a real voyage, actual NPC, boarding ticket, cabin berth or a local resident.** Native station traffic jobs still require named and physically available original NPCs. Regional/cold cohort ownership is deliberately not auto-attached to station UI without its canonical region/scope mapping and generation fence. The aggregate-demand adapter is ready for a later verified authority connection; an unbound population count is never presented as the station's current measured population.

## DOCK-06 — physical dock district and bounded original-NPC pedestrian flow

**Source development group, November 11, 2026; uncompiled and not installed/tested.** The goal is to replace generic visually moving crowd proxies for actual local dock activity with source-attested, deterministic and obstacle-aware named-NPC positions. This does not create additional persons, labor, ore, ship inventory, or independent intercolony transportation.

- `include/galaxy/Dock06Corridor.hpp`: one `dock06_walkers` table in the *same original world SQLite save* stores a maximum of 24 original named NPCs per local station/owner, with exact 2D native millimeter positions, three defined roles and finite route progress. The sub-station coordinate projection does **not** change the original Simulation's `NpcRecord::location` (ship versus station), residence or voyage identity. All records are readmitted from actual current shore-shift rows, real station-located boarding records or completed native ferry visitor arrivals. Wrong-custody and expired rows are removed; a large aggregate population never creates a walker.
- Native station movement has at most 250 mm per work pulse. Every path segment is screened at 50 mm intervals using the existing `NativeStationWalkGeometry.hpp` blockers, including physical corridor walls, freight crate and original berth marker. A conservative proximity test reduces walker overlaps. The three source-grounded routes are public passenger check-in to a gangway, a restricted dock worker dispatch route and incoming visitor walkway. An injured, unstabilized or otherwise medically unavailable original NPC does not become ambulatory merely because a visual corridor exists. Genuine emergency transport still needs original medical custody.
- `dock04::Traffic::serve_one` no longer jumps from the booked source hull through check-in, hatch and physical ferry in one uninterrupted handler call. It first commits the original named person's ship-to-station transfer. Subsequent native worker pulses advance that same original person through the station. The final original `HostEmbarkPassengers` command is admitted only after the source-attested walker reaches the gangway. Original assigned workers also must reach the independent dispatch point before receiving cargo/passenger throughput credit. No path visualization can grant employment or ferry custody.
- `src/desktop_station_host.cpp`: the protected original station writer now synchronizes/steps the finite corridor while performing bounded `DOCKWORK` service. New `DOCKPED` read protocol returns at most four verified named NPC IDs, native station millimeter coordinates and lane roles with original station/session/generation/request fences. The built-in 256-byte pipe boundary remains respected by the four-person cap. No separate Godot world-writing authority or uncontrolled frame-loop worker is introduced.
- Godot `native_station_session.gd`, `main.gd` and `dock_population_lod.gd`: authenticated native pedestrian frames are validated before displaying source-specific capsule positions; visual movement does not alter SQLite or ship/colony custody. The old synthetic walking crowd is suppressed once a real native corridor frame is present, preventing duplicate depictions. Four verified people can be displayed alongside bounded static population LOD; no pathfinding loop over a million residents.
- `colony_dock_layout.gd`: improves the **replaceable staging district**, matching the original C++ passenger, staff and visitor corridors with clear floor routing, gangway/security wayfinding, restricted-staff markings, and bounded ceiling lights. These decorative meshes are **not** physical facilities, electric power, navigation collision, original inventories, operational ship hardware or final creator-approved architecture.
