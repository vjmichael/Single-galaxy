# ECON-03c8b1 — Real-world detail-effect sealing (2026-11-01)

## Scope and authoritative boundary

This milestone extends the actual **PersistentWorld** SQLite integration from ECON-03c8a. It is **not** a whole-galaxy gameplay or simulation-Lod completion milestone. It provides a conservative, transactional **parked-world reconciliation** for executed mining, ore refining, and basic module fabrication.

The critical invariant is that all physical ore, modules, job identity, and player inventory remain in the **one real PersistentWorld snapshot**. The cold-region scheduler does not acquire a spendable copy of the same stock. Cold ownership currently parks this physical world: cold-time NPC consumption, factories, long-haul transport, ship trajectories, collision/physics and individual NPC simulation are **not** generated by this bridge.

## Implementation

- Added `PersistentWorldBridge::demote_preserving_effects(handoff_id)`. The old `demote_if_unchanged()` remains restrictive and backward-compatible.
- During the same SQLite ownership transaction, verifies that the current canonical detailed-world snapshot matches the real live PersistentWorld and that original mass/credit totals remain conserved.
- Seals every intervening `operation_log` generation, checks tick progression and final state hash, restricts executed applied commands to the first explicitly supported action set (Mine, RefineOre, FabricateModule), and verifies physical cargo-movement incidents against authoritative `resource_ledger` entries and command history. Unsupported movement/ship destruction/unproven physical incidents are refused instead of guessed.
- Writes `sg_world_cold_manifest` containing the exact persisted current-world snapshot, physical-world generation, operation count and incident count; appends unique immutable `sg_world_reconciled_movements` references to real incidents. These are **provenance receipts, not a second inventory**.
- Commits those records and the regional owner/generation flip together; SQL errors roll back the entire handoff. On a later promotion, the parked exact snapshot/generation is compared and its cold manifest consumed in the same transaction as the detailed anchor.
- Named NPC mining and fabrication continue relying on the original GRSM-04b execution receipts. The regional bridge does not invent or infer NPC actors.

## Limitations / next gates

1. This is an opt-in host bridge, not yet connected to the actual distance-interest scheduler or the game UI. Owners must explicitly request promotion/demotion.
2. While cold, real colony/NPC/factory/ship operations are parked, **not algebraically advanced**. The new region-level needs engine stays separate until its physical resource contracts and timeline are reconciled.
3. The action allowlist is intentionally narrow. Intercolonial hauling, ship docking/undocking/transit, factory networks, power/utility changes, casualty effects, construction and NPC migration still reject changed-world demotion.
4. Physical journal checks trust the local SQLite database, existing PersistentWorld restoration validation, and in-process host. They are not cryptographic authentication or permission for remote clients to submit arbitrary manifests.
5. The full reconstructed playable prototype is not a finished 3D game; Windows native graphical acceptance, multiplayer concurrency, complete collision/rendering, and whole-world performance remain open.

Next: real host-authenticated carrier loading/unloading, transfer receipts and zero-double-custody across detailed/cold boundaries, then actual cold-world production/consumption with bounded events.
